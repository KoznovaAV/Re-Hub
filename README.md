# ReHub — Сервис контроля передачи документов КЦР

Автономный веб-сервис для СКБ Контур, заменяющий разрозненные Excel-таблицы единой системой. Позволяет загружать срезы, автоматически рассчитывать динамику передачи оригиналов документов, формировать списки на обзвон и вести полную историю коммуникаций с клиентами.

## Архитектура и стек

Проект реализован как **модульный монолит** с выделенным AI-сайдкаром. Прямые интеграции с внутренними системами Контура отсутствуют, обмен данными происходит через Excel.

- **Backend (Go):** Ядро системы. Отвечает за API, бизнес-логику, парсинг Excel и расчет динамики.
- **AI Service (Python / FastAPI):** Изолированный сервис для ИИ-помощника (RAG на LangChain). Работает только на чтение данных, не изменяя состояние системы.
- **Frontend (Vue):** SPA с разграничением прав для администраторов и операторов.
- **Database (PostgreSQL + `pgvector`):** Единое хранилище данных (клиенты, срезы, события) и векторных эмбеддингов для ИИ.

## Структура проекта

```text
rehub/
├── backend/                  # Go-монолит
│   ├── cmd/api/              # Точка входа
│   ├── internal/             # Бизнес-логика (auth, clients, slices, workflow, ai)
│   ├── contracts/            # Спецификации API (openapi.yaml)
│   └── migrations/           # SQL-миграции
│
├── ai-service/               # Python AI-сервис (FastAPI)
│   └── app/                  # Логика RAG, эмбеддинги
│
├── frontend/                 # Клиентское приложение
│   └── src/                  # Компоненты, страницы, роутинг
│
├── docker-compose.yml        # Оркестрация локальной среды разработки
└── Makefile                  # Скрипты для автоматизации
```

## Быстрый старт

Для запуска всей инфраструктуры локально понадобятся только **Docker** и **Docker Compose**.

1. Скопируйте переменные окружения:
   ```bash
   cp .env.example .env
   ```
2. Поднимите контейнеры:
   ```bash
   docker-compose up -d --build
   ```
3. Примените миграции базы данных:
   ```bash
   make migrate-up
   ```

*После запуска: Go API доступен на `http://localhost:8080`, фронтенд — на `http://localhost:3000`.*

## Документация и контракты

Разработка ведется по принципу Contract-First. Единый источник правды для команды — спецификация OpenAPI 3.0 в файле `backend/contracts/openapi.yaml`. 
Она описывает эндпоинты клиентов, загрузку срезов, рабочий процесс операторов, ответы ИИ-помощника, а также универсальную модель ошибок и пагинацию.

## Ключевые функции MVP

- **Импорт:** Загрузка клиентов и срезов из Excel с валидацией и отчетом об ошибках (без дублей).
- **Динамика:** Автоматический расчет статусов (впервые появились, уменьшается, закрыт, повторный, хронический).
- **Рабочее место администратора:** Таблица с фильтрами, карточка клиента с историей, формирование списка на обзвон.
- **Рабочее место оператора:** Взятие клиента в работу (защита от одновременного доступа), фиксация звонков, список «Сегодня нужно».
- **ИИ-помощник:** Генерация сводок и ответы на вопросы по базе с указанием источников (защита от галлюцинаций).
