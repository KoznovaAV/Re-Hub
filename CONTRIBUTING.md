# Изменения и проверка Re:Hub

1. Создать ветку от текущего main и внести ограниченное изменение.
2. Проверить относящиеся к изменению сценарии и `git diff --check`. Команды запуска и тестов приведены в README.
3. Открыть pull request в main. Описать поведение, проверку и ограничения. Сверить контракт и документацию с изменёнными обработчиками.
4. Дождаться успешного CI: Python, Go с PostgreSQL, интерфейс, Compose smoke, безопасность и сборка образов. Исправить ошибки до слияния.
5. Проверить diff и сохранить замечания в PR или отчёте. Ревью другим участником желательно; наличие такого ревью не следует выводить из факта успешного CI.
6. Слить проверенный head, затем проверить статус main. Пропущенный release для коммита без тега ожидаем. Развёртывание зависит от настроенных секретов и не является частью локального smoke.

Тестовые пароли Compose предназначены для локального запуска. Секреты и рабочие строки заказчика в репозиторий не добавлять. Замеры программ и синтетические времена не выдаются за пользовательский пилот.

Применённые примеры процесса: PR #103, #105 и последующая [проверка готовности](reports/prototype-readiness.md). Правила защиты main и обязательное одобрение другим участником в настройках GitHub отдельно не подтверждены.
