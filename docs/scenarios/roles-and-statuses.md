# Роли и состояния после ревью

Основные свидетельства записи: 17:24-17:48, 19:26-21:14 и 28:57-31:48. Это уточнение заменяет старый прототип с административным переназначением.

| Действие | Администратор | Оператор |
|---|---|---|
| Импорт и подготовка списка | Да | Нет |
| Просмотр данных | Да | Рабочий пул, мои клиенты, общий рабочий список |
| Взять свободного клиента из подготовленного пула | Нет | Себе |
| Забрать клиента другого оператора | Нет | Себе |
| Передать своего клиента другому оператору | Нет | Да |
| Освободить своего клиента вручную | Нет | Да |
| Зарегистрировать претензию или санкцию | Да | Нет |
| Записать звонок, письмо, комментарий | Нет | Только назначенному себе клиенту |
| Закрыть клиента результатом "Отказ" | Нет | Нет |

Администратор не назначает операторов. Передача своего клиента коллеге выполняется через POST /clients/{external_id}/reassign; ручное освобождение — через POST /clients/{external_id}/release. Оба действия доступны только ответственному оператору и сохраняются в истории. Для передачи оператор использует POST /clients/{external_id}/take-over без user_id. Администратор получает 403. Назначение проверяется в транзакции; после передачи прежний оператор не может записывать взаимодействия.

## Разделение состояний

- Назначение: свободный клиент или ответственный оператор. Наличие ответственного не доказывает звонок.
- Статус звонка: не звонили, дозвон, недозвон, перенос, не тот контакт, обещание, отказ. Это рабочий справочник для повторного согласования с заказчиком, а не утверждённая финальная модель.
- Перенос звонка требует callback_on не раньше event_date. Последний звонок с датой переноса определяет напоминание. Новое взаимодействие-звонок заменяет прежнюю актуальную задачу. Комментарий не отменяет звонок.
- Обещание передать документы имеет promised_at. Эта дата не создаёт автоматическую просрочку звонка.
- Отказ сохраняется в истории. Он не закрывает клиента, не делает его неактивным и не стирает прошлое обещание.
- Неактивность и исключение поступают из справочника. Имеющиеся закрытые/неактивные записи не переписываются: причина старого состояния может быть другой.
- Системная история назначения сохраняется для аудита, но не считается историей общения и не участвует в числе звонков.

Из формы контакта убран выбор произвольного этапа. Окончательные правила закрытия, возобновления и переходов требуют отдельного согласования. До этого результат разговора не меняет этап автоматически.

## Что проверено

Тесты HTTP и PostgreSQL проверяют запрет административного назначения, передачу себе, сохранение callback_on/period_code новым HTTP-чтением, запрет записи прежним ответственным и сохранение активности при отказе. Контрольный список проверяется на 30 клиентах в двух периодах. Самостоятельный [эксперимент](../../reports/h00/automated.md) выполнен также на 4000 клиентах.

## Границы интерфейса

Основные экраны подключены к Go API/PostgreSQL. Сохранение назначения, истории, претензий и реальный импорт XLSX проверены в браузере, включая полную перезагрузку страницы. Режим в памяти включается отдельно через REHUB_MODE=demo. Реальная аутентификация не реализована: X-Role и X-User-Id остаются демонстрационными заголовками.
