# Ответственность Python и Go

Python получает XLSX и ImportContext по HTTP `/parse`, проверяет файл и возвращает ParserResult v1 с координатами строк и ошибками. Ответ проходит JSON Schema. Python не применяет правила истории и не пишет в БД.

Go уже вызывает рабочий парсер через `backend/internal/parser/parser.go`. Контрольный `/api/probe` проверяет доступность, а сквозная проверка реального импорта выполняется отдельно в Compose CI. Старое утверждение, что вызов парсера только планируется в #58, больше не актуально.

Go владеет проверкой дублей, справочника и периода, наследованием total, правами действий, preview и атомарным commit. Все экземпляры неоднозначного ключа отклоняются. Корректные строки сохраняются отдельно после явного согласия. Preview ничего не пишет; подтверждение повторяет проверку в транзакции. Отказ Python отличается от успешного импорта с нулём строк.
