## После ревью заказчика

[Новые требования](../scenarios/customer-review.md) заменяют старое правило полного отказа из-за дубля. Все экземпляры неоднозначного ключа отклоняются; корректные строки можно принять отдельно. История переназначений остаётся технической, а история общения содержит контакты с клиентом.

## Уточнение ролей после проверки записи

Администратор готовит список и не переназначает клиентов. Оператор забирает клиента себе. Результат "Отказ" не закрывает клиента автоматически. Перенос звонка хранится отдельно от обещания документов. [Модель и границы](../scenarios/roles-and-statuses.md).

## Уточнения реализации 22.11.2026

- Клиентов распределяют операторы. Администратор готовит пул; оператор может забрать чужого себе, передать своего коллеге или освободить вручную.
- Основные экраны подключены к Go API/PostgreSQL. Режим в памяти остаётся явной отдельной настройкой.
- Срезы сравниваются внутри отчётного периода. Значение «Всего» не переносится из другого квартала. Пропуск наблюдения не равен нулю.
- Реальный XLSX проходит предпросмотр, затем подтверждение. Частичный импорт требует явного согласия.
- [Результат самостоятельной проверки](../../reports/customer-requirements.md). Техническая корректность не заменяет пользовательский замер H-00.
