# Парсеры клиентов и срезов: T-01 - T-05

## Контакты и совместимость

Профиль `customer_kcr_directory_v1` ожидает лист `Все КЦР`, заголовок в строке 2 и данные со строки 3. Обязательны ключи выбранного режима, `Теги`, `Не нужно работать`, `Недействующий`, `Контакты`. Необязательное `Название` передается в `name`.

`Контакты` передаются отдельной строкой `contact_details`. Парсер не пытается угадать, где ФИО, телефон или почта. Это поле добавлено в ParserResult v1, Go DTO, импорт и ответы API. Миграция `003_contact_details.sql` добавляет соответствующую колонку. При повторном импорте отсутствие названия или контактов не стирает уже сохраненные значения; пустая контактная ячейка означает отсутствие обновления. Теги и флаги обновляются по действующему поведению импорта.

Переход со старой версии не переименовывает ранее импортированные организации автоматически: раньше контакты попадали в `name`, и без исходного файла восстановить название нельзя.

Дубли ключей остаются в ParserResult и проверяются Go. Для срезов ключом служит пара `external_id + period_code`. Парсер срезов возвращает отсутствующее `Всего` как `null`, а формулы и ошибки ячеек помещает в `errors` с источником. Наследование значения из предыдущего среза выполняется слоем чтения, не парсером.

## HTTP

`POST /parse`: multipart с полями `file` (XLSX) и `context` (JSON ImportContext). Оба типа файлов возвращают общий ParserResult. Ошибки строк и структуры книги находятся в `errors` при HTTP 200; вызывающий Go обязан проверять `scope=file` до сохранения.

Ограничения: запрос до 25 МиБ целиком с multipart-обрамлением, до 512 записей ZIP, суммарный заявленный распакованный размер до 200 МиБ. HTTP 413 означает превышение лимита запроса; превышение лимита архива возвращает `XLSX_LIMIT_EXCEEDED`. Неверный тип запроса дает 415, отсутствующие части - 400, неверный контекст или расширение - 422. Оборванный запрос получает 400.

## Проверки

```bash
cd parser-service
python -m pip install -r requirements-import.txt
python -m unittest discover -s tests -v
```

Тесты поднимают настоящий HTTP-сервер на свободном локальном порту, загружают справочник и два среза, проверяют ошибки контекста, тип файла, размер запроса и лимит распакованного архива. Фикстуры T-04 содержат 30 клиентов и признаки S-1 - S-8. Это проверка тестовых входов, а не подтверждение бизнес-гипотезы H-00.

Сквозной тест запускается в Compose в CI после основных smoke-проверок:

```bash
docker compose exec -T parser-service python - < scripts/smoke-parser.py
```

Тест пишет синтетические записи `SMK...` в тестовую БД, проверяет контакты, теги, исключение/неактивность, два среза и повторные импорты. Его следует запускать только на тестовом стенде.

## Производительность

Замер требует Linux/macOS для `resource.ru_maxrss`. Каждый прогон идет в новом процессе. Время измеряет разбор, без запуска интерпретатора; RSS включает весь процесс. Windows может использовать Linux-контейнер.

```bash
cd parser-service
python -m app.parser_benchmark /path/to/snapshot.xlsx ../contracts/examples/customer-october-context.json --repeat 5 --out /tmp/parser-report.json
python -m app.parser_benchmark /path/to/clients.xlsx ../contracts/examples/customer-clients-context.json --repeat 5 --out /tmp/clients-report.json
```

Отчет содержит хеши входа и контекста, версии, длительности, пик RSS и агрегаты; клиентские строки и контакты не публикуются. Фактические результаты и ограничения находятся в [отчете](../../reports/parser-completion.md).
