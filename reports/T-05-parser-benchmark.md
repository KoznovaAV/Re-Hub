# T-05 — замер парсера среза

**Дата замера:** 2026-11-19. **Статус:** синтетический полный прогон; реальный
XLSX заказчика в репозитории отсутствует, поэтому использованы публичные
агрегаты среза. Скрипт замера лежит в
[`ai-service/benchmarks/measure_snapshot_parse.py`](../ai-service/benchmarks/measure_snapshot_parse.py),
машиночитаемый результат — в
[`ai-service/benchmarks/results.json`](../ai-service/benchmarks/results.json).

## Вход

| Параметр | Значение |
|---|---:|
| Непустых строк | 12 772 |
| Разобранных строк | 12 772 |
| Уникальных ID | 4 205 |
| Ошибок разбора | 0 |
| Вкладки | Y2025 3 419; 2026Q1 2 928; 2026Q2 3 021; 2026Q3 3 404 |
| Размер XLSX | 239 298 байт |

## Результат

| Метрика | Значение |
|---|---:|
| Время, медиана 3 прогонов | **2,25 с** |
| Время, min…max | 2,16…2,28 с |
| Пропускная способность | ~5 660 строк/с |
| Пик Python-памяти (`tracemalloc`) | **10,62 МиБ** |
| Пик RSS процесса (Windows) | **82,9 МБ** |

Окружение: Python 3.9.13, Windows 10 (10.0.26200), AMD64.

## Как воспроизвести

```powershell
py -3 ai-service/benchmarks/measure_snapshot_parse.py --iterations 3
```

Для реального файла:

```powershell
py -3 ai-service/benchmarks/measure_snapshot_parse.py `
  --input path/to/snapshot.xlsx `
  --context contracts/examples/customer-october-context.json
```

## Ограничения

- Это не замер реального XLSX: синтетика повторяет только публичные агрегаты
  (12 772 строки / 4 205 ID) и типовые значения, включая числа с пробелами.
- `tracemalloc` показывает пик Python-аллокаций, RSS — пик рабочего набора
  процесса. Оба числа зависят от ОС, версии Python и openpyxl.
- Замер снят после доработки T-02; повторный прогон на реальном файле заменит
  синтетические числа без изменения кода и формы отчёта.
