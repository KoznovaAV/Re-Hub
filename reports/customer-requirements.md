# Реализация требований заказчика и самостоятельная проверка

Дата: 22.11.2026. Основа: main, коммит 5d3dab5. Ветка изменений: fix/review-roles-and-workflow.

## Что изменено

Основные экраны подключены к Go API/PostgreSQL. Импорт отправляет настоящий XLSX Python-парсеру, показывает предпросмотр и сохраняет данные после подтверждения. Режим в памяти включается отдельно через `REHUB_MODE=demo`. При недоступности рабочего API синтетические данные не подставляются.

При расхождении старого ТЗ и уточнений применены ответы заказчика В-10, В-17, В-18, сохранённые требования ревью и прямое исправление пользователя: распределением операторов занимаются сами операторы. Позднее ревью требует отдельной даты при переносе звонка; она отделена от обещанного срока передачи документов.

| Требование | Реализация | Проверка |
|---|---|---|
| Операторы распределяют клиентов | Свободного клиента берёт оператор; чужого забирает себе; своего передаёт коллеге. Административное назначение запрещено | Go HTTP/PostgreSQL, Vue, браузер |
| Освобождение только вручную | POST release доступен только ответственному оператору. Состояние и автор действия сохраняются, таймаутов нет | Go HTTP/PostgreSQL, Vue, браузер |
| Один текущий ответственный | Взятие выполняется условным UPDATE; передача и запись контакта блокируют строку клиента. Прежний ответственный после передачи получает 403 при записи | Go HTTP/PostgreSQL |
| Оператор не получает всю базу | Чтение workspace/clients ограничено пулом и назначенными клиентами; прямое чтение карточки вне пула запрещено | Go HTTP/PostgreSQL, браузер |
| Администратор формирует пул | Отдельное серверное действие; выбранные ID сверяются с допустимыми кандидатами | Go HTTP/PostgreSQL, браузер |
| Менее 5% исключать, кроме новичков | Точный порог без округления. Для новичка — явный тег или дата подключения. Ноль, исключённые, неактивные и закрытые не включаются | Сценарий S-6, Go HTTP/PostgreSQL |
| Независимые фильтры | Период, число документов, доля, тип, звонки по периоду, этап. Назначение не считается звонком; звонок с неизвестным периодом не выдаётся за отсутствие звонка | Vue и эталон из 30 клиентов, эксперимент 4000 |
| Сохранять предыдущие срезы | Записи разных дат сохраняются отдельно. Повтор того же периода и даты обновляет ту же запись без дубля | Go/PostgreSQL и S-2/S-4/S-8 |
| Корректная динамика | Сравнение дат внутри одного периода; полная передача отделена от частичного уменьшения; межквартальная разница не выдаётся за динамику одного долга | S-1–S-8 |
| Отсутствие наблюдения отдельно от нуля | Последнее известное состояние сохраняется; отсутствие клиента в последнем срезе не даёт права включить его в новый список | S-7, Go/PostgreSQL |
| Наследование «Всего» | Только из предыдущего среза того же периода, включая несколько последовательных пропусков поля | S-8, Go/PostgreSQL |
| Исторические взаимодействия | Фактическая дата события, дата записи и автор хранятся отдельно; исторический комментарий не переносит последний контакт назад | Go/PostgreSQL, Vue, браузер с перезагрузкой |
| Обещанный срок | Список: конец текущего месяца, конец следующего, своя дата. Выбранное название и рассчитанная дата сохраняются | Vue и API |
| Перенос звонка | callback_on отдельно от обещания по документам; дата видна в истории и рабочем списке | Vue, HTTP/PostgreSQL |
| Претензии и санкции обязательны | Администратор регистрирует вид, номер и дату официального письма, статус и комментарий. Карточка и история читаются из базы | Go/PostgreSQL, браузер с перезагрузкой |
| Ошибки XLSX и подтверждение | Настоящий файл проверяется до записи. По ревью неоднозначные дубли исключаются целиком, корректные строки принимаются отдельно только с явным согласием | Браузер, существующий парсер, HTTP API |

Исходные рабочие данные заказчика не публикуются. Для проверки используются синтетические наборы и тестовый XLSX. Администратор работает со всей базой; оператор — с рабочим набором. Новичок не выводится из самого факта появления нового долга: нужен явный тег или дата подключения.

## Самостоятельная проверка

1. `npm test`: 18 пройденных тестов Vue/правил, включая группы сценариев S-1–S-8, передачу, освобождение и исторические даты. [Протокол](h00/frontend-tests.txt).
2. `go vet ./...` и `go test ./...` с настоящей PostgreSQL. Проверены права, сохранение истории, запрет записи прежнему владельцу, дата переноса, отбор 30 клиентов, исключение клиента без свежего наблюдения и реквизиты письма. [Протокол](h00/workflow-tests.txt).
3. Полный браузерный прогон с Go, Python и PostgreSQL: пять групп сценариев, в том числе две полные перезагрузки страницы, самостоятельная передача/освобождение и загрузка настоящего XLSX. Ошибок JavaScript: 0. [Результат](h00/browser-workflow.json), [сценарий](../scripts/tests/live_workflow.py).
4. Программное сравнение XLSX в LibreOffice Calc и Go API/PostgreSQL на 30 и 4000 клиентах. Один разогревочный и пять зачётных прогонов, порядок чередуется. Во всех случаях списки совпали полностью, precision=1, recall=1, включений исключённых клиентов=0. Для второго квартала результат также совпал. [Времена, хеши и методика](h00/automated.md).
5. Пять тестов оценщика H-00 подтверждают, что один участник, неподтверждённый эталон или только скорость не дают статуса «подтверждена».

S-1–S-8 проверены как технические контрольные случаи. Спорные правила из исходного брифа не объявляются согласованными с заказчиком. В частности, истечение обещанного срока само по себе не создаёт красное предупреждение и не переводит клиента на следующий этап: применяется уточнение ревью о явном переносе звонка. Отказ фиксируется в истории и автоматически не закрывает клиента.

## Вывод по H-00

Техническая часть, проверенная этими сценариями, пройдена: сервис формирует правильные списки на контрольных данных, сохраняет историю и назначения, выдерживает проверенный объём 4000 клиентов. Это самостоятельный инженерный эксперимент, а не пользовательский пилот.

Гипотеза о двукратном ускорении работы администратора относительно Excel остаётся без пользовательского подтверждения. В эксперименте участвовали программы, человеческих участников 0; эталон синтетический и не утверждён заказчиком. Calc открывает заранее подготовленные формулы, API читает подготовленную базу. Отношение времён этих программ не является ускорением человека.

После технического эксперимента выполнена предварительная сессия с одним реальным участником: Excel B 36,076 с, Re:Hub B 7,329 с, списки правильные. Это отдельные наблюдения с разными границами таймера; полный пилот с двумя администраторами ещё не завершён. [Результаты и ограничения](h00/single-participant.md). Для текущего паспорта использовать [сводку готовности](prototype-readiness.md).

## Оставшиеся границы

- Вход и выбор роли остаются демонстрационными: используются тестовые идентификаторы и заголовки. Промышленная аутентификация не реализована.
- В прототипе доступны два тестовых оператора. Экран управления сотрудниками не добавлялся.
- Профиль предоставленного обезличенного справочника не содержит достоверных ИНН и отдельных телефонных полей. Неизвестные реквизиты не выдумываются. Поиск по ИНН работает при наличии ИНН в базе; неструктурированная контактная строка показывается как получена.
- Состав кампаний и окончательная статусная модель требуют согласования. Назначение не подменяет историю кампаний, отказ не закрывает клиента автоматически.
- Проверки выполнены на выделенной тестовой БД. Эксплуатационная база и внутренние системы заказчика не использовались.
- ИИ-помощник исключён из текущего main по ревью; это изменение не возвращает его из старой ветки демо.
