# Q-02 — E2E импорта

**Задача:** Q-02, MUST, A-13/P-03. **Статус:** автоматизировано; фактический
E2E-прогон выполняется в CI Compose.

## Проверяемые сценарии

| Сценарий | Ожидание |
|---|---|
| Валидный справочник клиентов | 30 строк принято, 0 ошибок |
| Повторная загрузка клиентов | `created=0`, `updated=30`, данные не потеряны |
| Срез с валидными и ошибочными строками | Preview показывает `accepted` и ошибки |
| Без `accept_partial` | `422 PARTIAL_IMPORT_REQUIRES_CONSENT` |
| С `accept_partial=true` | `201`, `status=partial`, валидные строки сохранены |
| Ошибки `DUPLICATE_KEY`, `CLIENT_UNKNOWN`, `INVALID_EXTERNAL_ID`, `UNSENT_GT_TOTAL` | Коды и координаты есть в ответе |
| CSV ошибок | Заголовок и по одной строке на ошибку; значения экранированы |
| Повторный импорт того же среза | Принятые строки не дублируются |

## Автотесты

- `scripts/qa/run_qa.py::q02` — API/БД, реальные XLSX и PostgreSQL.
- `frontend/src/import-errors.test.mjs` — сборка CSV, заголовок, экранирование,
  защита от формул, пустой список.

## Запуск

```bash
docker compose exec -T parser-service python - < scripts/qa/run_qa.py
```

## Результаты

До прогона в CI известные дефекты не фиксируются. Скрипт использует префикс
`QBA…`, чтобы не смешивать данные с smoke-набором `SMK…`. При падении в логе
остаются коды ошибок preview/commit и имя проверяемого файла.
